---
title: Bulk layout preparation
description: Private preparation for selecting and moving whole groups of binder slots.
---

Bulk layout editing is being prepared behind a private boundary. It is not enabled for ordinary binders or the public API.

The prepared controls require choosing **Edit layout**. Select saved slots across pages, or **Select page** to select the stored slots on the current page. Empty padding is excluded. The count shows the complete selection; **Clear selection** resets it.

Move the selection before or after another saved slot, or to the beginning or end. Slots keep their targets, copies and wants, in their saved relative order. Choose a destination outside the selection. Every action also works with buttons and keyboard, without dragging across pages.

Insert a number of free slots or a whole current-grid page at an exact saved anchor. Following slots shift automatically, including across pages. Changing the grid later repaginates them.

The private durable session says **Saved on device · Pending sync** only after a local storage transaction accepts the complete group. That does not mean a server has saved it. A changed layout needs review. Changed selected copies block the whole group until you clear selection and choose again. Failed local saves retain the original group for retry. **Done** exits editing without discarding accepted device edits.

Creating new copies from ordered catalog selections, bulk clear contents, cross-storage moves, public sync and rollout remain unavailable in this slice. Slot removal has a separate private consequence review below.

The local-only test host now exercises server command delivery as well as device saving. **Retry pending sync** preserves the original operation ID and request after a lost connection. A server receipt alone does not clear Pending sync: the session must read the complete current inventory after that reply. Billing and access failures pause the edit; conflicts retain it for review. An unknown outcome cannot be discarded or replaced to force a save.

This test path is not production admission. Public inventory/slot routes and native REST/MCP mutations remain unavailable. Native edits do not use the currently supported legacy Activity Undo command; native recovery, startup/offline relaunch, public API parity and the remaining rollout checks must pass before enablement.

### Staged native edit review

Native collection commands are still disabled in production. In the local test flow,
only a committed terminal rejection enables review. **Refresh current storage** loads
a complete private current read; **Use current storage** explicitly cancels that saved
edit. **Rebase saved edit** supports only nonoverlapping content or metadata changes.
Structural, overlapping and dependent edits stay retained for separate review.
A timeout, lost reply or unclassified conflict preserves the original command for an
exact retry, including after reload. No new command ID is chosen automatically.

### Recorded-copy bulk fill, private preview

In the local browser-host flow, choose **Edit layout**, then **Select several pockets**. Select saved pockets, then
**Fill selected pockets**. Review the actual copy ID and ordered destination ID
for every assignment. Choose a recorded Unassigned copy for each pocket, or
explicitly **Skip** it. Occupied pockets are preserved. Mismatched targets,
already-assigned copies, duplicate copy choices and unknown matching evidence
cannot be confirmed. Copied preset spacers and page padding cannot be filled.

**Preview automatic matches** proposes already recorded compatible Unassigned
copies for empty targets. It creates no cards or grades. Free pockets still need
an explicit choice or Skip. Review every proposal before **Confirm bulk fill**.
A single confirmation is one bounded atomic request, never several partial saves.
Choose a smaller selection if the request exceeds the existing limits.

Cancel saves nothing. If device saving fails, **Retry same fill** keeps the same
confirmed IDs and versions. Once accepted on device, closing the review does not
cancel pending sync. A server reply must be followed by a fresh complete read
before the saved request is acknowledged. There is no bulk Undo promise here.
This is still private preparation, not an enabled production or public API feature.

### Slot removal, private review

In **Edit layout**, select one saved slot and choose **Remove selected slot**,
or explicitly select several pockets and choose **Remove selected slots**.
Review the exact slots, targets and explicit wants that will disappear, and the
owned copies that will become **Unassigned**, then choose **Confirm slot removal**.
Every owned copy keeps its identity, grading and source metadata in Inventory.
Remaining pockets keep their order and current goals; the original preset stays
recorded independently. This does not delete a whole collection or remove ownership.

A removal is one bounded atomic request. Each selected slot and each assigned
copy uses one of the existing 256 work units. An unsupported group is rejected
whole, never split or silently shortened. Cancel saves nothing. **Retry same removal**
keeps the exact reviewed request after a device-storage failure. Device saving is
separate from sync and the fresh complete read that acknowledges it.

After synchronization, open **Activity** and inspect the recorded edit. Use
**Review recovery** when supported, review the current consequences, then confirm.
Newer edits, current permissions or unavailable history may block recovery.
This flow does not promise instant Undo or automatically identify a matching
Activity entry. Slot removal remains private preparation with production admission disabled.
