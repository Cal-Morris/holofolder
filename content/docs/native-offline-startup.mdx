---
title: Saved collections offline
description: What saved startup can show and when a connection is required.
---

Visit the app online first so this device can save its app files and collection data. Saved native collections can then reopen in Binder, List, Slabs and Inventory, labelled **Cached only**. Pending changes stay on this device until synchronization succeeds.

## Account and saved state

Saved startup, including on dead Wi-Fi that still reports online, needs the same unexpired device account session and saved collection-owner scope. Shared cached collections also need the account/owner-matched saved partner access allowance. This is permission to display saved copies, not proof of current membership or confirmation that pending changes reached the server.

Layout editing, new storage and remote commands are unavailable in cached startup. While initial account and membership checks are waiting, the app can show the saved view read-only and keep those checks running. It switches automatically to checked current data when access resolves. On reconnect an already cached view closes before access is checked again. Partner/account changes close the previous private view and its dialogs. Pending edits stay in their original scoped device record.

If a complete refresh fails, the app keeps saved copies and pending changes, shows why it cannot refresh and disables new edits. Use **Refresh storage** after reconnecting. Missing, corrupt or expired account evidence or saved metadata requires a connection; the app does not manufacture an empty collection or delete pending edits. A first-ever offline visit cannot open an app whose files were never cached.

## First collection

On a genuinely new account with no existing collection data, the server first proves the account is empty without creating anything. First creation also requires the server’s first-storage update, migration 098, to be applied and verified. Once it is available, choose **New storage**, preview the arrangement and confirm it. The first storage becomes your default after the server confirms the creation and the app reads current storage. A failed or unknown reply keeps the original creation pending; do not create a duplicate to replace it.

If the app says your native collection is not ready, existing or incomplete collection data still requires an administrator to finish conversion. A failed account or storage check cannot be treated as an empty account. The browser never converts existing legacy data automatically.

These startup and presentation preferences live on this device and add no REST or MCP operation. Existing native API credentials and server admission are separate from browser account checks. Physical-device and production verification remain release requirements.
