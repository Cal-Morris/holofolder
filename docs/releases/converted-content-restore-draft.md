# Restore contents in converted binders

Unpublished draft. Requires parent review, hosted migration 100, deployed behavior and publication approval. This is not a live availability claim.

Backup review can restore raw contents into the same converted binder using its existing pockets and physical copies. Choose a collection JSON backup, review each target, wanted card and placement, consent to any copies moving to Unassigned, then confirm. The original conversion evidence stays intact. Matching file IDs never prove provenance.

The original request is saved on the device before delivery. Lost replies retain it for exact retry, and a fresh current read is required before the device clears it. Recovery can undo the exact restore when its dependencies are still unchanged. No duplicate copies are acquired.

This bounded slice requires the same slot set, configuration, grid, copied manifest and origins. It does not restore a whole account, settings, assets, CSV, graded copies or a different structure. Copies placed in another binder must be resolved separately. Existing command and recovery size limits apply. Files with unverified wanted-card image URLs remain unsupported; no URL is silently removed. Hosted request/body/performance and installed-device checks remain parent gates.
