# Bounded raw restore review, unpublished draft

Status: staged implementation, not customer availability. Do not publish before parent admission, hosted verification and release acceptance. Full #365/#363/#379 remain open.

The native Backup flow separates local JSON inspection from explicit private planning for one matching raw collection. The additive v2 envelope allows up to 1,025 stable slots with exact copied manifest/origins, within 8,192 work, 1.75 MiB command and 2.5 MiB complete before/after recovery graph bounds. Existing wants and duplicated copied manifests count toward recovery size. Oversized intent stays unsupported; previously retained unsupported commands remain on the device and block edits. Review pages through all exact targets, wanted choices and placements in groups of 50, and asks for consent for every released copy. Released copies remain owned in Unassigned. Confirm saves the original bounded command on the device before delivery.

Lost replies keep the original command and operation ID. Editing pauses until a matching authenticated result and a separately fresh complete current read reconcile it. A rejected restore requires explicit discard and a new review before any replacement. File selection makes no upload or write; private planning is a separate disclosed action. No server backup store, provider lookup or file cache is created.

This does not restore graded or converted collections, other storage, slot creation/deletion, grid/configuration changes, changed copied manifests or origins, settings, assets or CSV. No ownership is acquired or deleted. Native production routes and REST/MCP stay fixed503. Synthetic browser evidence is not hosted or physical-device proof. Parent owns final review, integration, deployment, release publication and issue acceptance.
