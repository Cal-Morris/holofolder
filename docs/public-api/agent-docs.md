# Agent-readable developer documentation

Current server admission: supported native operations now use the existing authenticated bridges. See [the direct-cutover handoff](../native-direct-server-handoff.md). The historical slice notes below describe earlier staging and do not define the current fixed-503 policy. Hosted/app acceptance remains separate.

Public documentation is available without a login:

| URL | Content |
| --- | --- |
| `/app/llms.txt` | Guide and endpoint index linking to Markdown pages |
| `/app/llms-full.txt` | Every guide and endpoint contract in one text response |
| `/app/docs/llms.txt`, `/app/docs/llms-full.txt` | Equivalent URLs within the docs section |
| `/app/docs/markdown` | Overview as Markdown |
| `/app/docs/markdown/<page>` | A guide or endpoint as Markdown, using the same slug as its HTML page |
| `/app/openapi.json` | OpenAPI 3.1 REST contract |

Each HTML page advertises its `text/markdown` alternate and shows “View as Markdown” and `llms.txt` links. These paths retain the `/app` prefix and work through the public host or directly on the Vercel origin.

Fumadocs generates the index from the existing page tree. `lib/docs-navigation.ts` groups the long Collection and Prices and insights sections by subject for both the sidebar and agent index. The grouping preserves the generated operation URLs, Markdown paths and REST/MCP contracts; new operations without an assigned subject remain visible under Other operations. Guide Markdown is compiled from the same MDX with `includeProcessedMarkdown`; the Markdown-only Card, Callout and DocsLink renderers preserve useful labels, descriptions and links without exporting JSX. Endpoint Markdown serializes the exact operation from `public/openapi.json`, which is generated by `scripts/generate-api-docs.ts` from the operation registry. Do not maintain a separate copy of agent documentation.

Only public documentation and schemas are exported. These endpoints do not read account data or bypass API authentication. REST still requires a personal key; MCP uses OAuth. Missing response schemas remain undocumented rather than being guessed.

Verification: `bun test tests/docs-markdown.test.ts`; focused Playwright coverage in `e2e/docs-llms.e2e.ts` checks both indexes, all registered operations, exact endpoint contracts, discovery links and 404s. Regenerate OpenAPI after operation changes with `bun scripts/generate-api-docs.ts`.

Private committed history: use list_collection_audit/get_collection_audit with collection:read and current paid developer access. Follow nextCursor with unchanged filters; event IDs are strings. Unknown legacy actors are intentional. Recovery columns, certificate/label assets and share tokens are absent; no recovery command or structural mutation enablement is implied. Migration 076 is required, otherwise audit_unavailable is 503.

Native storage command/creation/recovery references are generated from the same registry with `x-admission: staged` and explicit 503 descriptions. Their schemas are not availability claims. The current `/app/docs/native-storage` guide and its Markdown/LLM exports explain the denied admission, supported backend contract, distinct native operation-ID replay, unchanged legacy Activity Undo and missing developer complete-read/pagination prerequisite. Agents must not use an unrelated browser session, public share or fabricated authentication to obtain private inventory state.

Native copy/storage/slot read schemas and `native-reads` help are exported by the same generators. They explicitly describe staged 503 admission, redaction and revision-bound pagination. Neither an agent export nor a returned developer page grants complete-snapshot/fresh-read ACK authority; certificates, private assets and immutable planning evidence are excluded.


The existing native command schemas also export optional `privateFields:preserve|replace`. Preserve mode requires `expectedOwnerUserId` and rejects a changed authenticated recipient before SQL, even without a prior receipt. Current help enumerates the safe preserve subset and explicit full-replacement compatibility. Agents must never reconstruct grading/wants from redacted reads or refresh an unknown operation's preconditions/recipient. Grading patches and redacted selected-want fulfilment require transactional executor support; no public admission or queue ACK follows from this preparation.

Copied preset discovery/preview is exported from the shared registry into OpenAPI, generated reference Markdown and LLM indexes, with staged admission and explicit unsupported set/master-set scope. The Presets navigation group classifies both new operations. Preview manifests are detached goals, not ownership, durable creation identities or complete planner/ACK evidence; see `/app/docs/preset-previews`.
Staged slot/inventory terminal rejection contracts are included in generated endpoint Markdown and full LLM exports: accepted 200 schemas remain unchanged, and 409 errors declare the strict `storage_command_rejected` envelope plus ordinary errors without proof. The native-storage guide explains exact original-ID binding, fresh-read review and unknown-outcome retry. MCP `tools/list` advertises accepted `outputSchema` and status-keyed errors in `_meta["holofolder.com/errorSchemas"]`; terminal tool errors have `isError:true` and matching text/structured JSON. Discovery never admits execution: public native calls remain fixed 503.

Migration 093 creation/import terminal contracts export `storage_creation_rejected` / `storage_import_rejected` and strict original-ID rejection bodies through the shared registry, endpoint Markdown and full LLM exports. Success schemas remain accepted-only. The native-storage guide states exact original family/request/owner/session binding, fresh authoritative complete reads and explicit reconciliation; neither schema validation nor an ordinary 409 permits discard. Native fixed 503 and separate durable consumer/hosted/admission gates remain unchanged.

Current identity contract (#509): use native inventory/storage APIs for copies, slots and wants. Public legacy species-row CRUD has no discovery/dispatch aliases. `get_pokemon_set_slots` is dex-grouped species data at `/pokemon/sets/{id}/slots`. Legacy history (`get_legacy_pokemon_analytics`) and `resolve_import` are removed. Activity filters physical copies by `inventoryItemId`. Existing durable command `itemId` fields are not renamed. Catalog cards/sets/series declare `game:"pokemon"`; application IDs/canonical IDs/reviewed aliases are globally unique and opaque. Source-keyed `externalIds` are provider-local evidence within the record game. No other game or selector is supported. Native server admission is enabled after #507; earlier fixed-503 staging notes are historical, not current policy.
