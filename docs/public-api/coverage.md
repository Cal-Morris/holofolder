# Operation coverage

This is the current inventory of what the public REST API and MCP server can do, and what stays in the app. The operation registry in `lib/developer-api/operations.ts` is the source of truth: it defines the REST paths and schemas, the MCP tools and the generated `public/openapi.json` reference. Every binder is native slot storage, and native reads and storage commands are admitted through the same authenticated bridges the app uses.

API keys are REST-only. MCP requires resource-bound OAuth with explicit grants. Raw API authentication ignores cookies and query-string secrets. Current membership and paid access (a Premium subscription or lifetime access, not a signup trial) are checked on every operation, otherwise the call returns `402 premium_required`. Images are R2-only, including private binder artwork in a separate bucket.

## App-only and device-only boundaries

- Website-only: billing and checkout, account deletion, API key and OAuth client administration, push-device enrollment, starting sold-comps checks and background comparison jobs (`ui_only`).
- Device-only: camera capture and OCR, page scanning, wake lock, offline storage and the durable command queue.
- First-party app routes use the signed-in session, not developer credentials: `/app/api/inventory`, `/app/api/binder-slots`, `/app/api/storage-collections`, `/app/api/native-recovery`, `/app/api/raw-content-restore` and `/app/api/collection-activity`. They share the same server operations as the registry, so behaviour matches, but they have no API-key requirement or developer paywall.
- Admin sync/backfill and payment webhooks are not public tools.

## Notes on specific contracts

- Public legacy species-row CRUD (`list_collection`, `save_collection_item`, `delete_collection_item`), legacy row Undo (`preview_collection_recovery`, `apply_collection_recovery`), `get_legacy_pokemon_analytics` and `resolve_import` were removed with the legacy `pokemon_collection` model, with no aliases. The first-party `/app/api/collection-analytics` route is removed too.
- Every writer records one `collection_activity` row itself (migration 108). History and recovery previews return `changes` projected to the fields Activity shows, so certificates, labels, artwork and share tokens never leave the server. A failed history read returns `503 audit_unavailable`.
- `list_collection_audit` with `operationId` filters to that exact operation. Zero results do not prove the operation never committed, and several results need `get_collection_audit` to pick the exact event. Activity filters physical copies by `inventoryItemId`.
- `get_pokemon_set_slots` at `/pokemon/sets/{id}/slots` is a dex grouping of species, not stable storage.
- Catalog cards, sets and series declare `game:"pokemon"`, with opaque global IDs and source-keyed provider evidence. No other game is supported.
- Native developer reads are pages and details, not complete snapshots. They omit certificates, private assets, immutable sources and planning evidence.
- Deleting a binder with its cards, as the app offers, is `execute_inventory_commands` with `deleteCollection` and `removeOwned: true` (migration 111). `delete_binder` keeps its older behaviour and releases copies to Unassigned.
- `restore_raw_collection_content` accepts command version 4 only and supports existing converted binders. Full-owner, settings, asset, CSV, graded and structural restores are unsupported.

## Verification

The [operator smoke guide](../api-smoke.md) runs every registered operation against a deployed environment with synthetic accounts. It has no native fixture lifecycle yet, so native operations are reported as uncovered. Focused unit suites cover the registry, dispatch and generated docs: `tests/developer-operations.test.ts`, `tests/developer-operation-round-trips.test.ts`, `tests/native-developer-operations.test.ts`, `tests/native-developer-read.test.ts` and `tests/docs-openapi.test.ts`.

The slice-by-slice rollout notes that used to follow this table described staged `503` admission and harness-only wiring that no longer applies. They are in git history, and the design records indexed in [docs/README.md](../README.md#native-storage-design-and-rollout-records) keep the invariants and proofs.

### Set year lookup and artwork

Search, Quick mode and Sets accept a four-digit release year, matching known set release dates. REST `GET /sets?year=2017`
and MCP `list_sets` expose the same filter with existing cursor pagination and optional series filtering. Set listings
include optional `symbol` and `logo` URLs for verified CDN objects; unknown artwork is omitted. UI result ranking and
on-device cached-set lookup are presentation/device behavior. See `content/docs/set-lookup.mdx`.
