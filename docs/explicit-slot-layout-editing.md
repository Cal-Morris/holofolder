This is private UI preparation on PR418's existing snapshot/draft boundary. Production bootstrap and the offline startup shell remain legacy-authoritative. Only the hard-gated synthetic `/app/e2e-harness?signedIn=1&slots=picker&rows=2&cols=2` supplies the callback. No schema, migration, hosted access, grants, conversion, authenticated execution or route enablement is added. #396 owns migration081 independently.

## Deliberate session

Edit layout is a labelled button on the binder view, only with the complete staged snapshot, signed-in context, catalog resolver and draft sink. The props do not authenticate or authorize a caller. Read-only/share callers have no editor. Presentation filters hide the control and exit editing; layout operations always resolve against the full saved array. Editing layout stays visible with Done, including in the selected slot's shared sheet. Page turning can continue while editing. Selection is discarded on page changes; editing and selection are discarded on account/owner/binder, view, presentation filter or dimension changes. Startup always begins in Browse. Nothing persists editing state.

Browse taps open the existing detail/picker. Browse holds, scrolling, page swipes and drags have no structural handler. A slot pointer records the current edit-session key at pointer-down. A changed session, cancelled pointer or movement over eight pixels prevents the pointer click selecting a slot. Structural buttons must receive their own pointer-down in the mounted editing session; native keyboard activation remains available. There is no drag reorder, long-press entry or bulk editor.

In editing, the sheet renders layout controls instead of duplicate card-picker controls. Insert before/after creates one new free slot at a stable anchor and shifts subsequent saved slots, including explicit spacers, across page boundaries. Append works without selection, including zero slots. Move earlier/later, to a 1-based saved position, or before/after a saved anchor moves the whole stable slot. Target, owned item reference, status, wants and preset provenance travel intact. Inventory items and placements are unchanged. Padding on a partial final page is not a stored slot.

## Internal callback/API

`onStagedSlotCommandIntent` now accepts `StagedSlotCommandIntent` from `lib/binder-slot-editing.ts`. It generalizes the existing picker envelope to `{ scope: { ownerUserId, collectionId, slotId: string | null }, intent: SlotOfflineIntent }`. Picker envelopes remain compatible. Null selection is used for toolbar append. Scope is a cancellation/routing fence, never authorization or an extra transport field.

`prepareLayoutIntent` emits only existing parsed `slots.create` or `slots.move` commands through `parseSlotIntent`, then validates the local preview using `projectSlotIntent`. Create carries its new stable ID. Move carries the selected slot/version, assigned item/version and placement/version. Both retain inventory, collection and layout revisions plus the original operation/occurrence/source envelope. Insert after uses the next saved slot as `beforeSlotId`, or null at the end. Position is resolved in the full layout after removing the moving slot; no filtered position is submitted. Invalid/missing/self anchors, scope mismatches and out-of-range/non-integral positions reject before handoff.

The same receiver boundary used by PR418 must synchronously retain the original envelope or throw **before accepting it**. A throw retains that exact draft for explicit retry, including generated slot/operation IDs and original revisions. Do not throw after acceptance or await remote execution in the callback. Cancel selection and all sheet dismissals discard only unaccepted local selection. Done exits editing, without revoking previous handoffs. There is no local Undo success message. A draft count in the synthetic harness measures only parser/projection handoffs, never durable acceptance, authentication, saved changes, replay ACK, acquisition/audit success or partner sync. Reload resets that synthetic projection.

The app, REST and MCP slot/inventory routes remain disabled. No operation is registered or advertised in OpenAPI. This is an intentionally internal boundary until #362/#383/#363/#413/#376/#379 supply supported authenticated execution, durable intent/replay/fresh complete ACK, permission/error/docs parity and enabled rollout proof. No new mutable ownership store or competing write path is introduced. The toolbar is dynamically loaded only when the private staged boundary is rendered; production callers do not render it.
