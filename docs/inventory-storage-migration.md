# Inventory storage and legacy conversion

Related: #361, #357. Schema preparation against main `b432b3c`; **not a runtime cutover or a completed hosted migration**. Applying `073_inventory_slot_storage.sql` creates no inventory items or converted binders. Existing UI, shares, REST/MCP and offline queues keep their legacy contract. No marketing announcement is warranted for hidden storage preparation.

## Persistence and authoritative state

Existing `binders.id` is `collectionId`. Names, default selection, ordering, grid overrides, appearance, shares and device cookies remain in their existing stores. No binder is replaced or automatically created. `storage_collection_state` adds kind/default presentation, metadata/layout revisions and a copied preset manifest without updating binder timestamps. No state row means `legacy`; explicit `legacy` means the same. `slots` with conversion version 1 identifies converted legacy storage. A newly created slot-native collection uses `slots` with explicit null conversion fields and starts with no implicit targets; the legacy converter rejects it. Unknown versions fail closed.

| Table | Purpose |
| --- | --- |
| `inventory_owner_state` | Owner-wide revision/serialization row, including the Unassigned selection absence predicate. |
| `inventory_items` | One physical copy per ID. Exact #382 identity/grading, nullable acquisition time, version and timestamps. No printing or certificate uniqueness. No collection FK. |
| `storage_collection_state` | Existing binder identity plus storage kind/presentation, revisions, copied manifest and conversion receipt. |
| `binder_slots` | Stable ID, unique saved position, target, explicit status/wants, provenance and content version. Position uniqueness is deferred for atomic reorders. |
| `inventory_placements` | Authoritative item-to-slot relation, at most one primary placement per item and one item per slot. Composite FKs enforce owner/collection agreement. |
| `binder_legacy_rows` | Frozen original row ID, deterministic slot mapping and **every original field** as JSONB, including unrecognized future fields. Import evidence, not a writable legacy mirror or audit feed. |

Map a stored slot to `BinderSlot.inventoryItemId` by its placement; there is no second item-reference column to synchronize. Map `StorageCollection.name` from the existing binder. Read order is `position,id`; independent item, slot, layout, placement, storage metadata and owner revisions map to the accepted pure contracts. SQL enforces safe-integer revision bounds, identity enums, wanted-choice validation, exact grading shape, scope and placement uniqueness. Deferred triggers enforce owned-status/placement consistency and require slot authority at commit. Future commands validate complete wants/targets/preset provenance with the existing domain normalizers and trusted catalog adapters; JSON storage is not authorization or catalog evidence.

Authenticated clients receive SELECT only. Policies require current owner/partner membership **and** the existing `billing_partner_allowed` predicate. Anonymous/public-share and MCP database roles receive no access. Public share projection/redaction remains an explicit server responsibility. Partner unlink immediately removes database access; queued/offline account isolation remains #363's responsibility.

Deleting a slot/collection cascades its placements and mapping records, leaving inventory Unassigned. The item retains original legacy source metadata independently of the deleted binder. Item deletion is separate; a deferred non-cascading FK prevents deleting a still-placed item. Account deletion can cascade all account-owned data without a restrictive-FK ordering failure. #383 must advance owner revision and record the release/delete in the same command transaction; cascades alone are not an audited command.

## One versioned conversion

The single implementation is `convert_legacy_binder_v1(collection, expected_owner, expected_rows_digest)`, a **service-role-only, unused SQL primitive**. `legacy_binder_evidence_v1` supplies a preview digest. It is not an endpoint and must not be called automatically during schema application, boot, cron or reads.

1. Resolve expected owner, lock that owner's inventory state, then lock the existing binder. Future multi-collection commands must use owner-first serialization and sorted binder locks. Legacy row writes lock the binder too, covering INSERT/UPDATE/DELETE and both sides of reparenting.
2. Return the existing receipt for an already converted binder. A lost response is retried with the same binder identity; it never recreates slots or reassigns subsequently moved items.
3. Compare the expected digest with the current complete source. A stale preview produces SQLSTATE `40001`; wrong owner `42501`; unsupported source `22023`. Nothing partial commits. Explicit repair/preview is required, never silently discard malformed source rows.
4. Materialize **all 1,025 targets**, position 0–1024, stable ID `legacy-dex-v1/<binder UUID>/<species>`. Copy National Dex v1 provenance and manifest. This ID is shared with `legacySlotId` for old queue reconciliation, not a runtime Pokémon-based slot identity after layout edits.
5. Map every source row to its matching slot and preserve its original UUID/whole JSONB. Every `collected`/`finalized` row becomes an item with **that row UUID as item ID**, plus one placement. Same printings in different rows/binders remain distinct copies. Null printing becomes `{kind:"pokemon",pokemonId}` with unknown grade; no guessed card, acquisition timestamp or grading is introduced. Wanted-only/considering rows create no items.
6. Copy wants in original order, including repeated choices and person/variant fields. Legacy wishlisted printing fields become an explicit choice only when the original want list is empty, using the original acquisition timestamp. Missing required metadata aborts conversion. Optional null display hints and `set_total: 0` become absent/unknown in the editable choice; **the verbatim original remains in `source_row`**. No legacy lossy/deduplicating client normalizer is used. `legacy_binder_wants_v1` is the sole SQL mapping helper.
7. Compare full source/mapping digests, item/placement counts and actual mapped item/status/want fields, then switch authority and increment owner revision in the same transaction. Receipt retains row/owned/wanted counts and digests, mapped digest, target count, actual item/placement counts and converted want count. MD5 over ordered canonical JSONB is a deterministic preservation checksum, not a security signature; backups use SHA-256. Source timestamp serialization is pinned to UTC.

Before commit or after any error/interruption, old rows remain authoritative and writable. After commit, direct legacy writes fail with SQLSTATE `55000`, `binder_converted_requires_slot_commands`, including service-role legacy routes. There is no caller-settable bypass and no dual write. A separate guard rejects downgrading slot authority erasing a live collection’s authority, or replacing conversion evidence, including stale service commands. The frozen source remains readable for evidence, **not** current collection state. Old readers are therefore insufficient for a converted binder: enabling conversion requires compatible readers/writers/shares/imports first. Parent binder/account deletion can remove frozen legacy rows while preserving inventory on binder deletion.

Partial/manual target residue conflicts with deterministic IDs and rolls back rather than overwriting it. Never delete residue blindly to make conversion succeed. Review its provenance and compare source/target snapshots. A transient deadlock, serialization error or connection loss is retried as a whole binder transaction with bounded backoff; after an unknown outcome, inspect authority/receipt before replanning. Do not retry `55000` through legacy routes. #363 must surface a converted-binder conflict and rebase the original intent safely.

## Pagination, guest identity and missing schema

`loadAllStoredSlots` pages through the existing `fetchAllRows` at 1,000 rows, rejecting partial results. #362 supplies owner/collection-scoped ordered queries and compares layout/content or owner revisions before/after **all** pages, retrying a changed snapshot. Inventory-wide reads also page by unique item ID. SQL conversion uses database-side scans/generate_series and cannot suffer PostgREST truncation. Empty targets do not count as inventory or billable saved cards; billing reads must switch to the agreed item/want semantics with #362/#383, not count slot rows.

`readStorageAuthority` falls back only for an absent state row or missing relation (`42P01`/`PGRST205`). Permission/network/unknown-version errors fail closed. This helper is unused until compatible adapters arrive, so deployments both before and after schema application keep working. Do not catch a write error and silently write the other store.

`legacyWorkspaceMapping` retains version, explicit local workspace identity, source collection ID and **each source row ID** with no receiving account. Guest IDs remain opaque; database adapters map an accepted workspace to a persisted binder UUID and retain source-to-destination mappings. Two same-printing local/remote rows are two possible physical copies, never implicitly deduplicated. Do not upload or retarget pending edits on sign-in/account switch/partner resolution without explicit recipient confirmation. #363 owns durable queue integration, original operation/source intent, transition preview/conflicts and device/account isolation; #365 owns accepted import identity. The helper is preparation, not an implemented guest migration UI. Existing signed-in defaults/grid/last-opened cookie remain untouched. First-use preset/blank navigation and sign-in/guest/offline flow verification remain rollout gates; no new allowance-consuming default is created here.
