# Atomic insertion plus explicit assignment (091)

Related: #375, #362, #383, #369. Staged backend and typed durable intent only. No production admission, hosted command/application, merge, conversion enablement or customer publication is included.

## Contract

`InventoryCommand.insertAssign` extends the existing inventory request and service-only trusted gateway, not the slot executor or a second transaction. Fields are required: `collectionId`, stable new `slotId`, `before` (exact existing `SlotPrecondition`, or null for append), `target` (explicit target or null/free), and `selection`:

- null: create only a target/free placeholder, never ownership.
- existing: exact `inventoryItemId` and `itemVersion`; the copy must still be Unassigned. Grading/certificate, acquisition and immutable source stay unchanged.
- new: explicit stable `itemId`, identity, grading and acquisition date. This is an intentional acquisition, with unknown values null. It does not silently substitute an eligible grade/copy. Callers review and choose eligible Unassigned copies first; no implicit assigned-copy move or scanner grading-policy expansion.

All inventory/content/layout revisions are retained from the complete snapshot. Before-anchors must be real existing slots in the declared collection, with current slot/item/placement versions. There is no fake destination reference. Insertion repaginates the complete saved order; existing target/wants/spacer/copy identities and versions stay intact. Slot version is 0 when empty, 1 when assigned; placement version is 0. Owner inventory, collection content and affected layout revisions each advance once per request, even for a batch.

Ordinary limits stay 100 commands, 32 collections, 256 selected affected entities, 256 KiB request, 1 MiB receipt. Additional insertion limits: 4096 slots per collection and 8192 order-work rows per request (sum of each current complete order plus its insertion). Existing audit/recovery limits stay 16384 entities and 16 MiB, with the original 10-second runtime deadline. Oversized evidence aborts; no truncation, chunking or increased timeout.

Original receipt replay after later edits or successful inverse returns the original result without recreating a slot, item, placement or event. Changed body/source/actor/recipient cannot borrow a receipt; current authority is checked before replay. It removes only the proved new slot/acquisition or releases the reused copy back to Unassigned, restores saved positions, and rejects stale layout, item, placement, dependency or ABA changes. Asset-bearing metadata restoration remains explicitly unsupported with `private_assets_unverifiable`; placement-only inverses can leave an existing copy's asset metadata untouched. It does not change frozen converted rows, mappings or conversion receipts.
