## Supported inverse

084 extends the existing private 077–081 planner/apply path for **genuine, complete, untouched nondefault native `collection.create` events generated by 083/076**. It removes the original binder, its native state and every recorded initial slot together. Blank, species/card targets, spacers, copied provenance, custom location and grid remain part of the recorded state, never guessed from a current preset. The full copied manifest must agree with every initial slot's identity, position, target, provenance, empty wants and null status. Both root insertions, the exact owner revision transition, and only the expected creation tables must be present. Missing or unsupported evidence rejects the entire event.

A first-native collection created beside an existing legacy default can be recovered. Its newly introduced `inventory_owner_state` is **retained**, with the current revision advanced once. This is a collection inverse, not an authority rollback. It never deletes inventory, demotes slot authority, converts a legacy binder, replays acquisitions or resets global counters. Existing copies, duplicate printings, grades/certificates, acquisition dates, explicit wants, legacy rows and other collections survive exactly. The unchanged storage authority guard permits collection-state removal only through the binder cascade; the executor does not bypass it.

**First/default creation is still blocked** by `creation_default_requires_explicit_replacement`. This slice does not choose a replacement, leave an implicit default decision to a legacy bootstrap, or mutate another collection to make undo work. A nondefault inverse also requires a surviving default, otherwise `creation_surviving_default_missing`. These are precise conflicts with no plan token. #396 remains incomplete and #379 stays blocked.

## Completeness, later edits and dependencies

The existing current-row/version and full later-history checks remain. Creation is stricter than ordinary content recovery: its entire native state, including content/layout revisions, must equal the recorded final state. Additional slots conflict even when they are absent from the original inverse. Later edits to this collection or its slots/dependencies conflict, including rename ABA and a subsequently removed share. Unrelated later owner/partner work survives. Later format-0, missing or empty versioned evidence yields `creation_history_incomplete`; absence is never inferred from partial history or a recent-event window.

All foreign keys referencing binders, native collection state or slots are inspected from the current database catalog, including future references. Only the fully evidenced native state/slots are allowed children. Every other occupied reference rejects with `creation_dependent_rows`, including inventory placements, legacy mappings/rows, shares, appearance, search history, public slugs and acquisition/delivery roots. Their old state is never deleted or revived as collateral cleanup. The reference definitions/absence and surviving default projection enter the private fingerprint; no tokens or dependent row contents are exposed. This avoids a hardcoded list silently missing a new cascading table.

Additional creation-specific reasons are `missing_native_creation_evidence` (unsupported), `creation_state_changed`, `creation_slot_set_changed`, and `creation_later_dependency_change` (conflicts). Existing named entity, layout, stale-plan and authorization reasons still apply. Unsupported/conflicted previews have no usable token; apply rejects all work. There is no force flag, ignored conflict, inventory cleanup, immutable-history rewrite, partial success or Unassigned alternative for creation.

## Locks, recorder and replay

Current membership is locked with `FOR SHARE` and rechecked before owner locks, also blocking non-key membership changes. Creation recovery then takes management lock 6102 before inventory/allowance lock 4701, matching legacy/083 creation. It locks all existing owner binders, including the surviving default, before its original native state/slot/item/placement/frozen-source locks. Binder/native-state/slot row locks also block new FK dependents while deletion is uncommitted.

All **three fresh plan reads** remain: initial dependency discovery, reviewed preview/fingerprint after locks, and final private plan. Default/reference changes between preview/apply invalidate the fingerprint. Revocation wins before owner locks or waits through accepted recovery's transaction. Conflicting later edits committed while dependency locking waits are caught by the fresh reads.

076 capture/flush/redaction/immutable guards, 079 validation behavior, 081 frozen restoration, current allowances and private runtime denials are unchanged. Recovery appends one linked `recovery.apply` event and the existing account-lifetime `recovery_v1` receipt in the same transaction. Recorder failure or statement cancellation rolls back roots, slots, ledger and history together. Exact replay after current authorization returns the accepted receipt; changed input conflicts. A creation retry after recovery returns its original historical 083 receipt and never recreates deleted entities. Fresh authoritative reconciliation is still required by #363. Ordinary deletion recovery can reverse this inverse using the same original collection/slot IDs, subject to current conflict/allowance rules.
