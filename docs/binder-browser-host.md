# BinderApp browser host binding

Related: #385, #386, #376, #379. This is an internal, denied-by-default binding of the actual BinderApp, not production admission. It requires no migrations or hosted writes.

## Admission and actual surfaces

`BinderApp` now imports the browser session and derives its scope from the current `useCollection` account and resolved owner. `useBrowserCollectionScope` checks JWT claims and current membership with the existing user/RLS client, keeps the JWT `session_id` separate from a random non-persisted lifecycle ID, and invalidates outstanding work before auth callbacks await. Account, owner and auth events replace the scoped session and close the actual rendered surfaces. Focus rechecks membership. Failed identity checks leave the existing legacy binder usable rather than authorizing saved JSON.

`browserHostAdmission` returns `rollout-379-incomplete` for production. Only the server-gated, non-hosted loopback E2E entry can supply `localBrowserHost`; a URL, saved navigation, user role, client environment flag or device record cannot admit the host. Public `/app/api/inventory` and `/app/api/binder-slots`, REST and MCP remain unchanged and hard503/staged. There is no conversion or production enablement in this PR.

The bound session renders the actual BinderApp grid, OrderedSlot, LayoutToolbar and SlotDetail, with its existing Search/Wanted/Browse dock destinations and shared Settings modal. Sign out delegates to the live outer BinderApp logout lifecycle. Inventory replaces List in that dock. Collection selection and Binder/List presentation are independent header controls; National Dex remains reachable, including Missing. Native List renders stable slots rather than substituting the legacy National Dex list. Wanted/Browse/analytics deliberately navigate to the labelled National Dex context and its live legacy collection, rather than interpreting an empty native projection as zero ownership. That selected legacy view is remembered locally. Native consumer parity remains #374. Slabs has no selector option and explicit Slabs links explain the Binder fallback.

The original collection hook stays mounted above native surfaces, preserving its legacy queue. Native surfaces use read-only legacy hooks and cannot write the legacy collection accidentally. The native IndexedDB queue belongs to account/owner/device/session above view remounts. Changing collection, presentation or history visit replaces transient layout/selection/overlay state, including when returning from Wanted/Browse. The runtime does not convert legacy queues or claim they are native intent.

## Reads, pages and device context

Only the winning initialization read can open navigation, so Strict Mode or overlapping refreshes cannot initialize a deep link against unavailable evidence. Every initial online read, reconnect/focus refresh and Open location calls the actual current-session HTTP adapter and complete-read reconstruction. No retained command reply or IDB JSON acquires completeness. Current scope is checked across awaits. Stable item/slot IDs resolve against a fresh complete read and its exact grid evidence; the actual grid highlights the resolved slot without opening an edit dialog. With unresolved local edits, location refresh is refused rather than resolving a remote page that may disagree with the optimistic layout.

Explicit binder/page/slot/item/view links beat remembered navigation. Explicit existing Wanted destinations stay on their legacy dispatch path. Auth and public-share routes do not mount this private host. Without a saved view or explicit link, the existing boot binder is only a fallback and is validated against available storage. Missing or uncached collections fall back with an explanation.

History and presentation stay in the existing account/owner navigation key. Page, native List search, Inventory query/window and the real scroll-container position survive history changes. The host observes native traversal entry changes as well as popstate, deduplicating both by scoped entry ID; this restores actual Next/browser history even when popstate is deferred. It synchronously changes its state reference when committing history and ignores unrelated/outgoing scrollers, preventing layout scroll events from overwriting the destination entry. Edit layout, drags, selected slots, overlays and highlights are never saved.

`holofolder-slot-device-v1` is a local device identity. The canonical queue remains in `binderdex-offline/records`, scoped by device/workspace/account/owner. Separate `slot-navigation-v1` metadata contains only catalog and grid evidence, parsed again against the saved queue baseline. IDB data is always cached evidence. Missing/corrupt metadata never invents grids. Locally projected slot commands cannot change the grid, so a matching baseline grid may follow their projected layout revision; unrelated mismatches remain unknown. Offline transitions downgrade remote evidence to cached. Failed refresh and view switches retain pending intent and clearly report Pending sync. Browser storage failure falls back to the legacy surface.

## Private API metadata

The existing private JSON-v2 catalog DTO optionally carries `pokemonIds`, taken directly from the already-paged public mirror `tcg_card_dex_ids` reads. No card-name inference, provider request, schema, grant, API registry or OpenAPI change is involved. Old metadata without these IDs remains display-only/unknown for target validation. Invalid/duplicate/nonpositive IDs reject the metadata. Translated names for the same printing can resolve one identity; conflicting canonical/alias/species evidence cannot. Display resolves each copy or exact target against its recorded language, with missing languages and ambiguous printing aliases left unknown; catalog insertion order never chooses the displayed card. Older strict private DTO parsers reject extended data rather than silently discarding it; no production reader is admitted yet.

Device navigation has no server mutation/audit event. The real native command controls enqueue through `useSlotOfflineQueue`, and Saved on device means transaction commit, not remote execution. Existing operation identity, scope, optimistic reprojection and post-command fresh-read ACK fences are unchanged. There is intentionally no browser send callback to the private executor while its first-party endpoint is unavailable. Pending records are not acknowledged, cancelled or dropped to make a test pass.

Supported inventory/slot REST/MCP parity remains required under #376/#379. This binding adds no supported public operations; the dedicated contract here avoids concurrent edits to `docs/public-api/coverage.md`. [Unpublished release text](releases/binder-browser-host-draft.md) must not be published as a shipped feature.

## Exact remaining authentic-admission gates

- Complete literal #379 blockers, including sharing, totals/wants/pricing, scanning, backup/full restore and audit/recovery/Undo, plus API parity. This PR does not complete #385's copy mutation/bulk inventory UI acceptance or #386's full gesture/Undo acceptance.
- Add a reviewed production admission capability and first-party authenticated complete-read/command HTTP dispatch after those gates. The current public routes must remain hard503 until then. Wire the actual command sender/retry schedule to the existing durable replay API; fresh reads may ACK only after matching replies and current-session scope checks. This host currently saves device intent but sends no command.
- Complete production native startup/offline-shell admission. [Cached startup preparation](native-cached-startup.md) now wires a display-only local-harness relaunch through canonical saved evidence; it does not grant current scope or sender authority. Current production `binder-start`, saved bootstrap markers and `offline-app-shell` deliberately remain legacy. An in-process admitted session can browse cached native data offline; a fully offline native relaunch cannot establish fresh JWT/membership proof in this slice and uses legacy startup. A reviewed compatible cached-auth admission/old-client strategy is still required, not a fabricated successful response.
- Parent must prove representative hosted conversion/counts/digests with a fresh restore-verified backup, existing offline queues/old tabs/SWs, owner and partner lifecycle, installed-PWA offline reopen, recovery and external API behavior on the deployed candidate. Native tables being empty and migrations 073–086 being applied do not establish this evidence.
- Slabs remains unavailable until #390's renderer. No marketing or publication until the corresponding capability is deployed and admitted.

## Verification boundary

`e2e/browser-host.e2e.ts` uses synthetic auth/ownership/catalog HTTP evidence with the real BinderApp/dock, private HTTP reconstruction and IndexedDB. It covers complete/503-cached reads, explicit links, stable location highlight, history return, native List filtering, in-process offline navigation, real layout enqueue/view teardown/reload, auth invalidation with an in-flight read and owner changes. The six phone profiles emulate standalone safe areas; they do not establish hosted RLS/load, installed-PWA or physical-device proof. Focused existing navigation, inventory, queue and transport suites remain independent regression evidence. Exact final commands/results are recorded in the PR. No full e2e or hosted writes.
