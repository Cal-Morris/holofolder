## Callback contract

`BinderApp` accepts optional `onStagedSlotCommandIntent` and `stagedSlotCatalog` alongside its existing complete private `stagedSlotDisplay`. Controls require a signed-in owner/partner context and an explicit selected stable slot; read-only/share callers never receive them. These props establish no authentication themselves and have no production caller. The eventual adapter must establish current account/owner/partnership and complete snapshot authority.

`SlotPickerIntent` contains `{ scope: { ownerUserId, collectionId, slotId }, intent: SlotOfflineIntent }`. Scope is a local routing/cancellation fence, never authorization or part of the transport body. The payload uses the existing `parseSlotIntent` contract and passes the canonical `projectSlotIntent` before emission. The draft retains original operation ID, occurrence time and source, independent inventory/collection/layout/slot/item/placement revisions and exact chosen-want index/value. Target, order, wants elsewhere and preset origins survive through canonical plans. The callback receives no catalog evidence, grading/certificate/label payload or forged actor.

Only deliberate card/grade/target/clear actions call the callback. Close, Cancel, X, backdrop, Escape, browser back, swipe and dock changes emit nothing. Disconnect dismisses an open sheet; opening again offline can search cached catalog data. Owner/account/collection changes discard unfinished selection; a previously handed-off intent remains the receiver's responsibility. A receiver must synchronously retain the original envelope or throw before accepting it. A thrown callback retains the same draft for explicit retry while the sheet is open; do not throw after accepting, await execution in this callback or treat closing it as revocation of accepted work. No durable acceptance or remote ACK is claimed. Unaccepted selections are disposable, not queued writes.

The synthetic harness parses again, projects against its synthetic complete snapshot, and counts draft handoffs. It does not authenticate, persist, reserve copies, execute SQL, notify partners, generate audit events or report success/sync. Reload resets synthetic state. Optimistic plans are not hosted proof.

## Supported draft intents

- `inventory.assign`, occupied `cancel`, selected catalog or explicit Unassigned item ID/version, optional one chosen want. An occupied slot must first be explicitly cleared, never overwritten. Placed copies are informational and cannot be selected for a default move.
- `slots.update` with a Pokémon target, printing/language/finish target, or null target. Removing target retains contents. Unknown/mismatched occupied evidence rejects the change; Cancel preserves everything. Clearing first is a separate explicit consequence, not an implicit compound operation.
- `slots.clear` for this exact slot. Ownership becomes Unassigned; target/order/wants/preset origins survive. The picker itself adds no remove-slot, insert, append, layout move, inventory delete or cross-storage move control. The separate [Edit layout preparation](explicit-slot-layout-editing.md) generalizes this same callback for staged create/move drafts.

The ordinary path reuses an eligible Unassigned Raw copy, otherwise creates Raw if no eligible copy exists. Recorded grading groups are explicit choices and send a stable existing ID, never silently substituting or cloning after conflict. Groups use full recorded grading equality and stable ID ordering; display labels contain only provider/grade and an ordinal when needed, never certificates or private label assets. Cards remain raw card presentation, not invented slabs. Catalog aliases/dex evidence constrain targets; no dex is required for a free slot. Unknown variants remain absent, not defaulted to English/Normal.

**Existing command limitation:** catalog selection cannot explicitly create Raw when eligible graded copies exist, or select a grading group atomically by predicate. The UI offers actual eligible recorded copies and states this restriction when only graded copies exist. Resolving this requires a reviewed #383 authenticated command/queue contract extension, not add-then-assign, fake ACK or an invented transport. Explicit ID/version conflicts never fall back to catalog creation. The full #366 Raw/grade acceptance remains open.

Online search uses the existing `/app/api/tcg-card-search?q=...&language=en&includeNonPokemon=1` public catalog read. The mirror uses a left dex join and retains rows with no dex only for that explicit mode; import and legacy search defaults retain their previous semantics. In the explicit catalog mode, a requested language is recorded only when localized-name or image-language catalog evidence confirms it; fallback display text/art does not invent that language. Offline search reads the existing cached catalog index. Non-dex search cards and alias evidence are retained. Missing cache coverage is stated clearly; this adds no service-worker caches of user HTML and does not claim durable offline assignment/reload/sync. Provider-confirmed finish options use the existing finish helper and recorded price evidence; the language selector requests real localized catalog results and records their actual language. Unknown and known-language cache entries stay distinct; cached alias evidence remains searchable.
