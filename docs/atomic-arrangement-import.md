## Supported execution modes

- **Arrangement into existing native storage:** one source collection, a complete trusted current-owner snapshot, a destination with an identical copied preset manifest, and explicit decisions for **every** imported physical item. The destination must be empty or contain only reviewed empty target/spacer slots, with no owned copy, status or wants. Its old empty layout is listed in `replacedEmptySlotIds`, version checked and replaced atomically with the complete imported ordered layout. An existing preset collection can therefore accept its saved arrangement without first deleting its targets in another transaction.
- **Explicit additional copies to Unassigned:** the original preview's bounded canonical inventory request now has an internal authenticated consumer. It discards arrangement/wants only in this explicitly selected mode. Every imported copy requires add-copy consent; existing 100-command/256-work/256-KiB limits remain. No chunked partial execution.
- **Same-owner unchanged restore:** remains a pure no-op only with verified same-owner export provenance and complete unchanged current state. Changed same-owner restore remains blocked, with no implicit extra physical copies.

Arrangement imports retain destination collection identity/name/kind/presentation/location and account appearance/settings. They import slots, not collection configuration. Any backup appearance/settings entry is unsupported before writes. An unequal manifest, nonempty contents, converted/frozen source or destination, grading label asset, unsupported combination or unresolved catalog/partner/copy decision fails explicitly. Collection-only exports carry assigned copies only. A one-collection all-inventory arrangement can additionally add explicitly selected Unassigned copies. Multi-collection atomic owner restore, arbitrary configuration replacement and CSV target-fill/append execution remain unsupported. CSV remains lossy interchange with preview-only helpers.

Foreign slot IDs are always remapped once in the recursively frozen preview. Add-copy decisions allocate new physical IDs once; use-existing decisions name exact trusted owned items, preserve their recorded metadata and expose explicit from/to moves. Each existing item can be selected/assigned once. No printing, alias or certificate establishes ownership identity or deduplicates copies. Foreign owner/auth/share/queue fields are never authority. No backup URL is fetched. Asset/label bytes and cross-account private URLs remain #390 work and are rejected here.

## Transaction, revisions and retry

088 adds only `collection_audit_private.import_arrangement_v1` and one branch in the existing `storage_execute_v1` gateway. The private helper has no runtime EXECUTE grant. Existing owner executors, parsers, `slot_saved_count_v1`, immutable 076 accumulator/flush, recovery planner and `developer_idempotency` are reused. No parallel receipt/history store or deadline increase.

The gateway rechecks trusted actor/source, developer billing and operation identity. Import locks live membership `FOR SHARE` before owner lock 4701, then owner root, collection metadata/layout rows and selected item/placement/slot refs. It requires exact owner inventory revision, every affected source/destination content/layout version, full old empty destination slot refs and exact item/version/placement refs. Selected existing identity/grading/acquisition values must still match. This prevents a partner's move, metadata ABA, unlink or changed layout from silently overwriting intent. Converted authority/receipts/frozen sources are never rewritten.

One transaction adds new copies, releases explicitly moved source placements while retaining targets/wants/provenance, replaces only the reviewed empty destination slots, inserts complete ordered imported slots/placements, checks all target matches and current owner allowance, advances owner and affected content/layout revisions, appends one actor-attributed `backup.arrangement` event and stores one permanent `backup_arrangement_v1` ledger receipt. Failure, cancellation, deferred audit failure or allowance rejection rolls everything back. Targets/spacers/manifests cost no saved entries; owned copies and explicit wants/considering status use the existing aggregate.

Exact replay returns the original safe receipt before mutable revision/catalog checks but only after current membership/entitlement admission. Changed body, actor, credential/source or accepted owner operation reuse conflicts. A receipt is historical acceptance, not proof that later partner moves have not happened. IDs are never upserted or regenerated. Limits are 8 MiB UTF-8 intent, 4,096 imported slots, 4,096 reviewed empty destination slots, 5,000 copies, 32 affected collections, existing 16,384-delta/16-MiB audit admission and a 1-MiB receipt. Bounds reject whole intent, never truncate or chunk it. Receipt fields are `inventoryRevision`, `collectionId`, `collectionVersion`, `layoutRevision`, `changed`, ordered `slotIds`, `addedItemIds`, `removedEmptySlotIds`. Private grading/certificates/evidence are excluded.
