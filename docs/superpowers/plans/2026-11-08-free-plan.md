# Useful free plan implementation plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan inline, task by task.

**Goal:** Ship issue #303: 100 saved entries and one free binder, preserving existing data and offline edits.
**Architecture:** Database-owned allowance values are returned by the existing billing RPC and retained in the account/owner-scoped cache. Existing collection guards consume those values; a serialized database trigger enforces binder creation. Before migration, signed-in clients retain the old 10-entry/20-binder policy. Guests use the new local 100-entry allowance.
**Tech Stack:** TypeScript, React, Next.js, Supabase/PostgreSQL, Bun.
**Spec:** https://github.com/Cal-Morris/binderdex/issues/303

## Global constraints

- One concern, one separate worktree and PR. Leave #304–#307 unchanged.
- No e2e tests. Keep current prices, share gates, partner/comparison entitlements and Dex layout.
- Keep the 20-binder safety ceiling. Retain all existing cards/binders after expiry and rollback.
- No secrets in logs/diffs. Apply only this task's new numbered migration after inspecting hosted schema.

## Review focus

- Old billing RPC/cache must keep its conservative limits before migration; expired cached subscriptions retain server free limits.
- Concurrent inserts across binders must never exceed 100 entries; direct binder inserts cannot evade the one-binder policy.
- Default-binder creation must remain idempotent under simultaneous requests.
- Over-limit updates, deletes and edits in existing extra binders remain available.
- Billing pauses must retry when an allowance changes, without dropping queued edits.
