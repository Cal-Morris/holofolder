# Manual per-copy grading drafts (#387)

Status: staged internal UI, not enabled or shipped. Source baseline: `56aef3cd0b9ac23873468300e264963f9e8e28a4` (2026-11-09). #385's production inventory binding and #379 rollout are still pending. No BinderApp/navigation, queue/session, SQL, creation or recovery code changes. No hosted migration or data writes.

## Editor adapter contract

`components/grading/grading-editor.tsx` consumes a canonical `InventoryItem`, its stable `InventoryItemRef` (exact item/version plus placement/slot predicates), current-owner item evidence and callbacks. It clones the canonical `GradingRecord` into a local working draft. Raw is `null`; a graded record may have an unknown (`null`) grade and certificate. All text uses the existing `normalizeGradingRecord`, including its 500-character/20-subgrade limits. No numeric conversion or new grade normalization. Known providers are selected with canonical IDs/spelling, including **Beckett**. Custom providers and grade/style text remain text. Certificates retain leading zeros, punctuation and exact supplied strings.

Optional fields cover scale/version, designation/qualifier, named subgrades, holder/version and explicit label variant/custom style. Existing private asset IDs survive edits; no upload or asset entry (#390). Provider changes retain entered metadata and ask the user to review it. Blank means unknown; invalid canonical data remains in the draft with an error and cannot be accepted. Reference notes flag unsupported numeric/text choices for review without deleting legacy data or mapping CGC legacy grades to modern grades. No inferred Black Label, Pristine, label art, barcode or authentication claim.

- `onAcceptDraft(editCommand)` accepts a **local draft only**. UI says “Use grading draft”. The host must never describe this callback as persisted. No callback fires for typing or cancellation.
- `onCommit(editCommand)` is an optional future durable adapter, not wired to production here. Only `{ kind: "persisted" }` permits successful close; rejected/thrown/incorrect enqueue receipts keep the draft open. The adapter must resolve persisted **after** its authoritative transaction commits, never after optimistic enqueue. Dismissal before submit changes nothing. Dismissal while a submitted save is pending cannot undo that operation; the editor explains this while waiting. Late results cannot close a newly mounted copy editor.
- Command is exactly existing 075 `{ kind: "edit", item: InventoryItemRef, grading: GradingRecord | null }`. It cannot add/reacquire a copy or mutate identity, placement or acquisition. The host must supply a current full `InventoryCommandRequest` with operation ID, inventory revision and affected collection tokens, establish authenticated owner/partner access and trusted `AuditContext`, recheck all predicates in 075, and integrate the existing audit/recovery and replay contracts. This PR does not fabricate transactional history or prove persisted/offline replay/conflict behavior.
- Host must unmount on account, owner, evidence or reference changes. The wrapper resets local state on item ID, owner, version or placement-reference changes. Opening a different editor must replace the previous overlay. `useOverlay` handles focus, scroll lock, Escape, browser/Android back and `closeAllOverlays`; `useSwipeToDismiss` handles the header gesture. Cancel/X/backdrop/swipe/host tab switch discard unsent edits.
- Duplicate warnings compare exact provider+certificate only against supplied current-owner evidence, excluding the current item. No global query, merge, authenticity or uniqueness assertion. Missing/partial evidence cannot prove uniqueness.

The synthetic local-only `/app/e2e-harness/grading` follows the existing Inventory harness gate: `HOLOFOLDER_E2E=1`, no Vercel environment, loopback Host only. It cannot enable the production inventory or binder-slot routes, which remain hard 503. Harness draft state is in memory, explicitly not persisted, and never an account/session or queue adapter. Production callers remain absent.

## Private provider navigation

`ProviderRecordLink` is **private-owner UI only**, including its certificate-bearing href. It uses normal external anchors (`target=_blank`, `noopener noreferrer`, `no-referrer`), no Next prefetch, fetch, cookies, headers, scraping or background lookup. Copy uses the clipboard with selectable text fallback; both manual entry and copy remain usable offline, external navigation needs a connection.

Official references checked 2026-11-09:

| Provider | Record navigation policy | Primary evidence and access limits |
| --- | --- | --- |
| PSA | Exact 8–9 ASCII digit strings generate `https://www.psacard.com/cert/{certificate}/psa`. Other formats use the official lookup page. This finite link rule is not a validator for every historical PSA certificate. | [Security](https://www.psacard.com/security), [lookup](https://www.psacard.com/cert), and actual official [8-digit record](https://www.psacard.com/cert/21498270/psa) / [9-digit record](https://www.psacard.com/cert/168163120/psa) were readable through web retrieval. Cookie-free curl to the issue-supplied cert path returned HTTP 403 with `cf-mitigated: challenge`; working outbound links do not prove server access. |
| ACE | Official lookup + Copy certificate, no guessed certificate path/query. | [Official scale](https://acegrading.com/grading-scale) links to [cert lookup](https://acegrading.com/cert). The lookup returned 403. No direct-record format established. |
| CGC | Official lookup + Copy certificate, no guessed certificate path/query. | [Official scale](https://www.cgccards.com/card-grading/grading-scale/) links to [verification](https://www.cgccards.com/certlookup/). The verification page returned 403. No direct-record format established. |
| Beckett | Official lookup + Copy certificate, no guessed certificate path/query. | [Official card lookup](https://beckett.com/grading/card-lookup) was readable and expressly allows links to this lookup page. No certificate-specific URL established. |

Only the verified PSA `/cert/8-or-9-digits/psa` path is parsed from pasted URLs. Exact allowlisted HTTPS host (`psacard.com` or `www.psacard.com`), no credentials, ports, encoded/path-normalized inputs. Provider mismatch is rejected rather than silently changing provider. Parameters/fragments are discarded locally and not persisted. Custom and unknown links are unsupported in this slice, not stored/fetched. A certificate is not forced into a URL format; unsupported formats retain their original text and use lookup fallback.

Grade reference review: [PSA](https://www.psacard.com/gradingstandards), [ACE](https://acegrading.com/grading-scale), [CGC](https://www.cgccards.com/card-grading/grading-scale/), [Beckett](https://beckett.com/grading) were readable. ACE lists integer 1–10 and qualifiers; CGC documents half-grades, text designations and a legacy key; Beckett documents half-point grades and multiple labels. These sources inform advisory review only. A recorded overall 10 never implies a particular designation/label or artwork. Manual details stay user-recorded, not provider-verified. Automatic retrieval (#391/#392) and assets (#390) remain separate, unimplemented capabilities. [PSA's API](https://www.psacard.com/publicapi/documentation) requires authenticated access; no credentials or bypass were used.

## API and privacy boundary

No supported REST/MCP operation, registry/schema, generated OpenAPI or public help contract changes. The editor only produces the existing internal 075 edit intent. #376 owns supported API parity before any exposure; #379 owns rollout. Existing hard-503 routes are untouched. The staged internal API exclusion is intentional, not an undocumented missing endpoint.

No grading data is added to existing public serializers or public shares. `ProviderRecordLink` must never receive a private record in a public component. Publishing a slab, binder or showcase must not publish certificate strings, URLs, labels, asset IDs, slab photos or nested serialized values by default. The existing browse projection still excludes certificate/holder/label fields. The separate scoped certificate-publication permission chosen in #387 remains **off, unimplemented here**: there is no production sharing scope/preview/revocation adapter to bind it to. Do not infer permission from general share visibility. A later explicit permission flow must cover both text and href, preview and revocation/invalidation before publication.
