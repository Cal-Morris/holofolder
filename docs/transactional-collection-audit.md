## Capture and trust boundary

An AFTER row trigger accumulates **only touched entities**, retaining each first before state and final after state. A deferred constraint trigger writes one event per owner/database transaction before commit. Cascading collection deletion and a bulk RPC therefore produce one logical event, not 1,025 notifications or snapshots of the owner's whole inventory. A recorder error, size error or duplicate operation ID aborts the mutation, its ledger result and its acquisition/outbox effects. Rolled-back work, ledger replay, pure reads/previews and timestamp-only/no-op updates produce no event. A change and its inverse within one transaction disappear only when all retained state/versions actually match.

Capture covers current `pokemon_collection`, `binders`, `user_settings`, `binder_shares`, `binder_appearances`, and the six 073 storage tables. It includes direct authenticated writes still allowed by RLS and service writes, independent of which route/RPC performs them. `record_collection_activity` retains 032's indexed price observations; its old per-row event insertion is replaced by transactional consolidation. Acquisition intent and partner push outbox code are unchanged. Structural/grade/layout changes do not call acquisition delivery. Analytics projects bulk legacy Pokémon deltas and excludes structural entries; old event columns and values are untouched.

The authenticated app boundary uses `withAuditActor`, and the shared developer dispatcher supplies the verified principal, transport and credential **identifier**. An async-local context, never inbound audit headers, is attached only by the service-key client's fetch. Every PostgREST transaction gets its own operation UUID; the enclosing app/API request ID is the batch ID. Existing idempotency ledgers remain authoritative for mutation replay. `075` retains its accepted operation/batch/client occurrence identifiers in the event. No key material or OAuth token is copied.

SQL accepts the internal context header only when the actual PostgREST role is `service_role`, validates the actor exists and holds a linked partner row through commit when actor differs from owner. An authenticated caller cannot elevate attribution by setting the same header or an arbitrary audit GUC. Direct authenticated writes use the JWT user ID with source `direct`; they do not infer the owner as actor. Unwrapped service/SQL writes are **Unknown**, even if their JWT contains an owner's ID. Future named service jobs can use `withAuditSystem` at a trusted server entry point; no currently nonexistent job/action is claimed implemented. Unknown historical events remain format 0 with Unknown actor/source.

The SQL-owner-only 074/075 commands keep their authorization, entitlements, owner locks and ledger boundaries. Their returned trusted context is attached to the pending transaction. Inventory command evidence stores the returned per-command **before** evidence and the **final root `after`** plus final inventory revision/acquired IDs. Intermediate per-command after versions are deliberately excluded. The consolidated deltas also retain first/final ownership, placement, item, slot, collection, layout and owner revision state, including null creation/deletion states. Conversion is captured via the storage authority transition/receipt, not a grant or new conversion route.

`recorded_at` is the server's `clock_timestamp()` in the deferred recorder immediately before commit. PostgreSQL cannot expose the future exact WAL commit timestamp inside that same transaction; this field is server acceptance/commit-boundary time, never a claim of a client clock or precise WAL commit time. `client_occurred_at` is a separate optional, untrusted chronology hint from an accepted original intent. Existing app paths do not invent one.

## Retention, privacy and size

Event metadata and compact touched-state evidence are retained for the owner's **account lifetime**. No price-history 90-day cleanup applies. Actor/entity IDs are deliberately not cascading FKs; deleting an item/slot/collection or changing a display name cannot erase or rename its evidence. The account FK still cascades for explicit account/privacy deletion. Ordinary clients and service-role callers cannot rewrite/delete/truncate the ledger, and cannot insert fabricated events directly. Only the recorder inserts. TRUNCATE is rejected on captured tables because it bypasses row triggers/RLS; use an authorized row deletion instead. Database administrators remain trusted operators.

`changes` is the safe private read projection. `recovery_state` and `command_evidence` are server-only columns, unavailable to authenticated SQL clients and never selected by REST/MCP/history analytics. Private certificate strings, label metadata/assets, private uploaded artwork references and legacy-source blobs are removed from read projection. Share capture allowlists metadata and **never stores the token**, even in recovery evidence. No headers, bearer credentials, JWTs, provider payloads, push queues or signed artwork URLs are captured. Developer reads also reuse the existing R2-only image sanitizer. Current appearance/config state and revisions are retained for safe recovery; restoration must validate referenced assets and current entitlement. Cross-owner reparenting is rejected rather than copying another owner’s before-state into an unrelated history; an actual transfer feature requires a reviewed integration. Public share functions receive no audit surface and retain their existing public redaction rules.

The accumulator uses two private transient tables (one transaction header, one row per touched entity), emptied transactionally at commit. It does not repeatedly rewrite a growing bulk JSON object. Per-event raw touched-state admission is 16,384 changed entities / 16 MiB; overflow aborts rather than silently truncating recovery evidence. This is a safety ceiling, not a supported command size or an invitation to make unbounded snapshots. 074/075 retain their stricter request/result/work bounds. Local synthetic 1,025-row capture size/timing is recorded in PR evidence; production capacity and account-lifetime growth need measurement before broad exposure. No silent archival/purge policy is introduced.

## Supported private REST/MCP reads

The existing registry adds `list_collection_audit` (`GET /collection/audit`) and `get_collection_audit` (`GET /collection/audit/{id}`), with `collection:read`. Existing credential grants, current membership resolution, paid developer-access enforcement and private/no-store response handling apply on both transports. No public/anonymous audit access exists. SQL reads separately enforce owner/current linked partner plus billing eligibility.

List uses descending bigint event ID keysets, limit 1–100 (50 default), with filter-bound opaque cursors. It supports collection/item/slot/actor/action and server date bounds. IDs are returned as strings. Deleted-entity filters use retained affected IDs, not a live-entity join. Format-0 historical events lack stable entity IDs, so entity-specific filters cannot promise to find them. Detail selects the same safe projection and returns 404 for an absent/other-owner event. Missing 076 returns 503 `audit_unavailable`; there is no silent empty-history success. The old analytics endpoint falls back to its original columns before 076.

Synthetic example:

```http
GET https://app.holofolder.com/app/api/v1/collection/audit?limit=50
Authorization: Bearer <collection-read-key>
```

The response has `data` and `nextCursor`. Each entry includes actor kind/account/job, source/client identifier, operation/batch IDs, server/client times, action, retained affected entity IDs and redacted before/after deltas. A legacy entry has format 0, action `legacy`, Unknown provenance and its original Pokémon states. Read-only app Activity consumes this reader through the first-party session adapter described in [collection-activity-ui.md](collection-activity-ui.md). Recovery execution remains separate issue #396.
