# card-assets

This folder decides **which image each card shows, where it comes from, and why**. Read this before adding an image source, changing which source a set uses, or touching the image backfill scripts.

It is built on the [PTCG Image Atlas](https://github.com/nstrelow/ptcg-image-atlas) by Luna ([live map](https://nstrelow.github.io/ptcg-image-atlas/#v=network)). The atlas maps where Pokémon TCG card images come from: which official sites publish them, who scans or re-hosts them, who copies whom (pixel-verified where possible), what TCGdex is missing per language, and whose permission reusing each source needs. We keep a pinned copy of its `data.json` and key our sources to its ids, so its research (kind of image, size, permission) drives our choices. Credit Luna's atlas whenever you explain why we use a source.

## Layout

The folders mirror the image bucket: brand first, then game. Only `pokemon/tcg` exists today. A future `pokemon/tcg-pocket` or another brand gets its own folder with the same files.

```
card-assets/
  AGENTS.md                      this file (CLAUDE.md points here)
  pokemon/tcg/
    sources.csv                  every image source we know about, keyed to the atlas
    rules.csv                    which source we prefer, and where
    atlas/data.json              pinned copy of the atlas data (MIT, see atlas/LICENSE)
    atlas/SOURCE                 the atlas commit it was copied from
    ledger/en/<setId>.csv        what each card ends up with (generated by `plan`, committed)
lib/card-assets/ledger.ts        the pure logic: parsing, rule matching, choosing, atlas cross-check
scripts/card-assets.ts           the CLI, the one entry point for card images
scripts/card-assets/             its collection subcommands (mirror-tcgdex, mirror-pokemoncom, fill-gaps, inventory)
tests/card-assets.test.ts        unit tests, including parity with the app's image choice
```

## Commands

| Command | What it does |
|---|---|
| `bun run card-assets plan [--set a,b]` | Reads every card from Postgres (read-only), applies `rules.csv` and rewrites the ledger. Prints counts by source and kind, and the weak images: no image, a foreign print, or a retail photo. |
| `bun run card-assets verify [--bucket holofolder-assets]` | Fails if `sources.csv` or `rules.csv` is invalid, an `atlas_id` doesn't exist, or the committed ledger is out of date. Reports how many cards the ledger picks differently from what the app serves today (`differsFromApp`); that's expected after a rule change until it is published. With `--bucket`, also counts chosen images missing from `card_image_inventory`. |
| `bun run card-assets migrate-bucket [--apply]` | One-off move of every `cards/...` object in `binderdex-card-images` to `pokemon/tcg/cards/...` in `holofolder-assets`, with server-side copies (no downloads), then records the new bucket's keys in `card_image_inventory`. Without `--apply` it only reports what is missing or differs (exit 1 if anything does), which doubles as the post-move check. Needs `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID` and `R2_SECRET_ACCESS_KEY` for a token that reads the source and writes the destination. |
| `bun run card-assets discover malie` | Finds malie.io's renders for every set in `malie-sets.csv` (TCG Live JSON exports for SV and ME, TCG Online listing pages for HGSS through SWSH), matches them to our cards by collector number **and** name, and writes `discovered/malie.csv`. Cards whose name disagrees are left out. Commit the CSV with the ledger. |
| `bun run card-assets publish [--set a,b] [--apply]` | Makes the app show the ledger. For each card whose chosen image differs from what the app picks on its own (`pickCardImageUrl` without published entries), it uploads the image to R2 if it isn't there, checks it landed, records it in `card_image_inventory`, and writes `external_ids_json.assets.en = { image, source, rule }`. Cards whose choice matches the default lose their entry. It refuses to run while the committed ledger is out of date, and it revalidates the app's mirror cache with a sync when `CARD_DB_SYNC_SECRET` is set. Needs `CARD_IMAGE_STORE=r2` and the app's `R2_*` variables. Dry run without `--apply`. |
| `bun run card-assets renditions [--set a,b] [--apply]` | Stores the 320 px copy (`<key>.low.webp`) beside every chosen fallback-source image that lacks one. `publish` does this for the images it uploads. |
| `bun run card-assets mirror-tcgdex [--set a,b] [--from id] [--lang en] [--quality high,low]` | Copies TCGdex images (and each card's fallback-source image) into R2, resumable, with the `--concurrency`, `--max-class-a` and `--max-gb` budgets. The same code backs `POST /api/admin/mirror-card-images` and the image step of `sync-card-db`. |
| `bun run card-assets mirror-pokemoncom [--set a,b] [--dry-run] [--recheck]` | Copies pokemon.com's official images into R2 and records them on each card (`external_ids_json.pokemoncom.image`). |
| `bun run card-assets fill-gaps [--apply]` | Fills catalog gaps from public sources: reviewed images for cards TCGdex has none for, cross-source aliases, and promo sets TCGdex doesn't list (rules in `lib/card-gap-fill.ts`). |
| `bun run card-assets inventory` | Rebuilds `card_image_inventory` for the app's bucket from an R2 LIST (after manual deletions). |
| `bun run card-assets atlas` | Refreshes `atlas/` from the atlas repo's `main` and lists atlas sources we haven't classified yet. Review the diff before committing. |

It needs `POSTGRES_URL_NON_POOLING` (or `DATABASE_URL`) in `.env.local`. Nothing here uploads to R2 or writes to the database yet; publishing is phase 3 of the plan below.

## `sources.csv`

One row per image source.

| Column | Meaning |
|---|---|
| `id` | Our source id. Must match `CardImageSource` in `lib/card-image-sources.ts` (plus `tcgdex`) for sources the app serves. |
| `kind` | `official-render` (game-client or official site renders), `official-scan` (scans published by an official site), `rehost` (copies of other sources), `fan-scan`, `retail-photo`. |
| `permission` | `none` (fine to use), `granted` (someone said yes, recorded in the note), `needed` (ask first), `forbidden` (terms forbid it). Rules can only prefer `none` or `granted`. |
| `permission_note` | Why the permission is what it is: who agreed and when, which terms forbid it, or why we use a source the atlas flags. |
| `hosts`, `max_size`, `credit`, `credit_url` | Where its images live, the largest size seen, and how to credit it. |
| `atlas_id` | The source's id in `atlas/data.json`. Empty only for sources the atlas doesn't list (playshop). |

Images that aren't recorded on the card rows come from `discovered/<source>.csv` (columns `card_id`, `url`, …), written by `discover`. They are candidates like any other, so a rule decides whether they win.

The licensing stance: card artwork is © The Pokémon Company, so no source comes with a licence. We rely on long-standing tolerance, which is well established for official digital images (the atlas's "no extra permission"). Fan scans can carry the scanner's own rights, and some sites forbid mirroring, so those stay `needed` or `forbidden` until someone actually agrees. `verify` warns when we allow a source the atlas flags and the note doesn't say why.

## `rules.csv`

The mapping of which source we prefer for what. One row per decision.

| Column | Meaning |
|---|---|
| `scope` | `*`, `series:<id>`, `set:<id>` or `card:<id>`. A trailing `*` matches a prefix (`set:tk-xy-*`). The most specific scope wins: card, then set, then series, then `*`; an exact id beats a prefix, and a longer prefix beats a shorter one. |
| `lang` | The card language the rule is for (`en` today). |
| `prefer` | Source ids in order, separated by `>`. The first source that has an image for the card wins. `reviewed` means the card's hand-reviewed catalog image (`external_ids_json.catalog.image`), whatever its host. |
| `reason`, `decided` | Why, and when. Write the reason for someone who wasn't there. |

The `*` rule encodes the app's default order (`pickCardImageUrl` in `lib/card-image-sources.ts`), and `verify` proves it: `differsFromApp` is 0 when nothing else is pending. A token can name a language: `tcgdex:en` matches only TCGdex's English print, while a plain `tcgdex` matches a print in any language. To change a set, add a more specific row, run `plan`, and review the ledger diff: it shows exactly which cards move from which source to which.

pokemon.com's images are only 245 × 342, so the default order puts them after TCGdex's English print (600 × 825) and before any foreign print.

## The ledger

`ledger/en/<setId>.csv`, one row per card, regenerated by `plan`. Don't edit it by hand.

| Column | Meaning |
|---|---|
| `card_id`, `local_id`, `name` | The card (`tcg_cards`). |
| `rule` | The scope of the rule that decided it. |
| `source`, `kind` | The chosen source and its kind from `sources.csv`. Empty means no image. |
| `image_language` | For TCGdex images, the print's language. Anything other than `en` is a foreign print shown to English collectors. |
| `url` | The origin URL. The app serves its copy from R2 (see below). |
| `alternatives` | Every other image we know of for the card, so an upgrade is visible without fetching anything. |

## Correlating ids across sources

Every source names cards differently. This is where each mapping lives.

| What | Id or key | Where it's stored or computed |
|---|---|---|
| Our card | `tcg_cards.id` (TCGdex id, e.g. `sv01-001`), with `set_id`, `series_id`, `local_id`. Imported promo sets use `tcgplayer-<productId>`. | `tcg_cards`, synced by `lib/card-db-sync.ts` |
| TCGdex image | `https://assets.tcgdex.net/{lang}/{series}/{set}/{localId}/{high\|low}.{ext}`. `image_languages_json` lists the languages TCGdex has. For sets missing from TCGdex's asset manifest, `external_ids_json.tcgdex.image`. | `buildTcgdexAssetImageUrl`, `pickImageLanguage` in `lib/tcgdex-shared.ts` |
| pokemon.com | Its own set code (`SV01`) and number: `…/cards/web/SV01/SV01_EN_1.png`. Recorded on the card as `external_ids_json.pokemoncom.image`. | `pokemonComSetCode` in `lib/pokemoncom-card-images.ts`, `bun run card-assets mirror-pokemoncom` |
| pokemontcg.io and Scrydex | `external_ids_json.pokemon_tcg` (`imageLarge`/`imageSmall`), matched during the sync. Either host can appear there. | `lib/card-db-sync.ts` |
| TCGplayer | `external_ids_json.tcgdex.thirdParty.tcgplayer`, or the first `variantThirdParty[].tcgplayer`. | `lib/card-image-sources.ts` |
| Scrydex, Limitless and playshop picks | Chosen per set by the gap-fill rules, stored as the reviewed catalog image. | `GAP_IMAGE_SOURCES` in `lib/card-gap-fill.ts`, `bun run card-assets fill-gaps` |
| malie | TCG Live exports use malie's set keys (`me6`, `mebsp`, `svbsp`, `zsv10-5`) and TCG Online listings use the game's codes (`SF`, `CZ`, `Promo_SM`, `TK5A`). `malie-sets.csv` maps each of our sets to one of them; numbers are compared without zero-padding (`SM01` = `SM001`) and names with energy symbols spelled out. | `malie-sets.csv`, `lib/card-assets/malie.ts`, `discovered/malie.csv` |
| Atlas sources | Atlas source ids (`pcom`, `pokemontcgio`, `malie`, …) map to ours through `atlas_id`. The atlas has no per-card data, only per-source facts and per-language gap counts, so it informs rules rather than matching cards. | `sources.csv`, `atlas/data.json` |
| R2 object | `pokemon/tcg/cards/{lang}/{setId}/{localId}/{high\|low}.{ext}` for TCGdex copies, `pokemon/tcg/cards/src/{source}/…` for the rest (bucket `holofolder-assets`). Old `cards/…` keys and URLs map across with `currentCardImageKey` in `lib/tcgdex-card-image.ts`. From a URL: `developerImageKey` in `lib/developer-api/image-identity.ts`. | `card_image_inventory (bucket, object_key)` records what is stored |

## Where this is going

The plan, with the audit behind it, is in Cal's plans repo (`holofolder-card-image-sources-2026-11-11`). In short:

1. **This folder**: sources, rules, ledger, `plan`, `verify` (done).
2. **New bucket and prefix**: everything lives in the `holofolder-assets` bucket under `pokemon/tcg/` (for example `pokemon/tcg/cards/en/sv01/001/high.webp`), still on `assets.holofolder.com`. Old `/cards/…` URLs keep working through a Cloudflare rewrite (done).
3. **malie**: `discover malie` and `publish` (done).
4. **Stored sizes**: `large`, `medium` and `small` WebP per card instead of resizing in the proxy.
5. **One script**: the old `mirror-card-images`, `mirror-pokemoncom-images`, `fill-card-gaps` and `sync-card-image-inventory` scripts are now `card-assets` subcommands in `scripts/card-assets/` (done).
